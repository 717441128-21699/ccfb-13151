# 地方麻将规则配置与验证平台 —— 规则引擎核心

把“每接一种地方玩法就硬写一遍代码”变成“策划在浏览器里配一份 JSON 规则包”。
本仓库是平台的**同构 TS 引擎核心**：浏览器配置台与 Node 服务端跑同一份代码，
无任何运行时依赖，Node 24+ 原生执行 TypeScript。

## 解决的问题

- 接新地方玩法不再写代码：番型、杠、花、赖子、吃碰杠优先级全部声明式配置；
- 任意一手牌摆上桌即可验证：能不能胡、几番、怎么拆番最大、听哪些牌；
- 规则说明自动生成给运营，文档与线上规则同源；
- 人工核对的黄金牌局逐手回归，算番结果一手都不能错。

    fan-engine.ts       算番：包含覆盖 / 互斥组 / 起胡线 / 封顶 / 最优拆分

    doc-generator.ts    规则包 → 运营可读 Markdown
    sichuan.ts          四川血战（演示子集）

## 关键设计决策

### 1. 赖子与天然牌分离计数

赖子不计入天然 `counts`，单独用 `wildcards` 表达；“赖子变成什么”由拆分算法
在 DFS 中按需决定，而不是输入层定死。两张赖子互配为将时先保留 `wildRemaining=2`
的紧凑语义，再由展开器枚举全部 34 个目标牌种参与番型比较。

### 2. 2ms 穷举是怎么做到的

- 永远从编号最小的非零牌种分支，每个节点只枚举包含该牌的组，消除排列重复；
- `quickReject` 预检在 O(n) 内证明明显无解的散牌（孤立单张数 > 赖子数）；
- 跨调用死状态备忘录（两级数字键，无字符串分配）让失败状态全局剪枝；
- 栈式回溯（单数组 push/pop）消除热路径数组分配。

实测（Node 24，10000 手批次）：最坏的无解散牌稳态 **222µs/手**、冷批 238µs，
端到端含算番 **81µs/手**，均远低于 2ms 预算。逐样本 max 可能出现 GC 毛刺，
因此基准以批次均值 + p99 为判据，详见 `benchmark/bench.ts`。

### 3. 番种关系是数据，不是代码

规则包里每个番种声明 `predicate`（谓词库注册名）+ `includes`（覆盖谁）
+ `mutexGroup`（与谁互斥）+ `value`。新增常见番种只改 JSON；只有各地极特殊
番种才需要在 `predicates.ts` 登记新谓词并补测试，避免规则包退化成代码。

### 4. 边角规则按规则包分流

一炮多响、抢杠胡、海底捞月、杠上开花都在 `claim-resolver.ts` 按规则包开关处理，
同一引擎适配各地差异；胡法（自摸/点炮/抢杠/杠后摸/海底）通过 `GameContext`
注入，番型谓词只读上下文。

## 常用命令

```bash
npm test          # 全部测试（单元 + 性质 + 黄金牌局）
npm run golden    # 仅跑人工核对的黄金牌局
npm run typecheck # 严格 TypeScript 类型检查
npm run bench     # 2ms 预算性能基准
npm run demo      # 端到端演示（胡牌/算番/最优拆分/听牌）
```
